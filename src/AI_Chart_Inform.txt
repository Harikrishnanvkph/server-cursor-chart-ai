  "data": {
    "labels": ["Entity A", "Entity B"],

        "borderColor": ["#3b82f6", "#10b981"]
      }

  },
  "user_message": "A message for the user about the chart data."

Only return the JSON object, with no markdown or additional explanation.

FIELD DESCRIPTIONS:
- chartType: The visualization type (see list below)
- title: A concise, descriptive chart title based on the data topic
- subtitle: A brief subtitle that adds context (e.g., time period, source, or key insight)
- xAxisTitle: Descriptive label for the X axis (e.g., "Month", "Region", "Product Category")
- yAxisTitle: Descriptive label for the Y axis (e.g., "Revenue (USD)", "Temperature (°C)", "Count")
- grounding: Extract verified figures and time period first before emitting the data array
- grounding.verifiedMetrics: Array of { entity, value, unit } representing the verified real-world data points
- data.labels: Category labels for each data point (must correspond to grounding entities)
- data.datasets[].label: Name of each dataset series
- data.datasets[].data: The actual numeric values (must strictly match the values in grounding.verifiedMetrics)
- data.datasets[].backgroundColor: Colors for each data point (use visually appealing rgba colors)
- data.datasets[].borderColor: Border colors for each data point

The chartType must be one of the following: "bar", "line", "pie", "doughnut", "scatter", "bubble", "polarArea", "radar", "horizontalBar", "stackedBar", "area", "pie3d", "doughnut3d"
IMPORTANT: If the user asks for a "3D pie chart", use chartType "pie3d". If the user asks for a "3D doughnut chart", use chartType "doughnut3d". If user asks for a horizontal bar chart, use "horizontalBar". If user asks for a stacked bar chart, use "stackedBar".

4. Each dataset must have its own descriptive "label" (e.g., "Net Worth", "Current Revenue"), its own "data" array of numbers matching the labels length, and distinct colors.

All arrays (e.g., labels, data, backgroundColor, borderColor within each dataset) must be of the exact same length.

DATA PRECISION & FACTUAL INTEGRITY RULES:
- DEFAULT TO LATEST: Unless the user explicitly requested a past historical year (e.g. "in 2020"), ALWAYS default to the freshest, most up-to-date data available as of today.
- Use exact, verified facts and figures. Do NOT fabricate, extrapolate, or hallucinate numbers.
- For dynamic metrics (net worth, market caps, prices): use the latest live tracker or market close numbers.
- For annual/periodic metrics: use the latest officially reported completed period.
- "grounding.verifiedMetrics": ALWAYS generate the "grounding" object BEFORE the "data" object. Extract the entities and numerical values from verified research/context FIRST into "grounding.verifiedMetrics".
- "data.datasets[].data" MUST contain strictly numbers (e.g. [14.5, 29.8], NEVER strings like ["$14.5M", "29.8%"]). The values in "data" MUST match the exact numbers extracted in "grounding.verifiedMetrics". Put currency/unit symbols in "yAxisTitle".
- When search results or research summaries are present, extract real figures directly from them.
- If real figures for a specific data point are unavailable, state clearly in "user_message" which figures could not be found, rather than inventing fake data.

AXIS TITLES:
- For bar, line, area, scatter, bubble, horizontalBar, stackedBar charts: Always provide meaningful xAxisTitle and yAxisTitle
- For pie, doughnut, polarArea, radar charts: xAxisTitle and yAxisTitle can be empty strings ""
